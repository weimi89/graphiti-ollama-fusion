# 搜尋命中率評估報告（階段 5B 大樣本驗證）

> 日期：2026-06-20　樣本：150 筆分層 golden set（78 node + 72 edge，跨 15 group）
> 工具：`tools/evaluate_search.py` + `src/search_eval.py`；baseline：`data/eval_baseline_full.json`
> 可重現重跑：`uv run python tools/evaluate_search.py run --golden tests/fixtures/golden_full.json --recipes node_rrf,node_mmr,combined_rrf,edge_rrf,edge_mmr --k 10 --per-group`

## 方法論

1. **分層取樣**：依各 group 的 Entity 數比例，從前 15 大 group + global 取樣（最大餘數法，每 group 至少 2 筆），避免樣本集中於最大 group。
2. **golden 持久化**：LLM 從 entity summary / edge fact 生成「不含實體名稱」的自然語言查詢，存檔一次、之後零 LLM 可重現評估。
3. **度量**：recall@k（目標是否進 top-k）、MRR（目標平均排名倒數）。node 目標對 `node_*`/`combined_*` recipe，edge 目標對 `edge_*` recipe。

## 核心發現

### 1. 真實命中率（推翻小樣本假象）

| recipe | recall@10 | MRR | 命中 |
|---|---|---|---|
| edge_mmr | 1.000 | 0.968 | 72/72 |
| edge_rrf | 1.000 | 0.944 | 72/72 |
| node_rrf / combined_rrf | **0.795** | 0.484 | 62/78 |
| node_mmr | **0.436** | 0.206 | 34/78 |

- **edge/fact 搜尋近乎完美**（recall 1.0、MRR≈0.95）。真正弱點是 **node 搜尋**：~20% 目標連 top-10 都進不去，MRR 0.484（平均排第 2）。
- 先前小樣本（8–20 筆）測得 node_rrf recall@10=1.0 是**取樣假象**；150 筆才看出 0.795 的真相。

### 2. node_mmr 在大樣本上有害（mmr_lambda=0.9 是過擬合）

階段 2 曾在 15 筆樣本上測得「mmr_lambda 0.5→0.9 把 node_mmr recall 從 0.20 救到 0.867」。但 150 筆顯示 node_mmr recall@10 僅 **0.436**，遠低於 node_rrf 的 0.795。結論：**MMR 的多樣性懲罰本質上犧牲召回**，即使 lambda=0.9 仍劣於 RRF。所幸 `search_memory_nodes` 預設走 RRF，未傷及 production；但 `node_mmr` 不應作為精確查找的推薦策略。

### 3. recall ceiling：~14% 的 miss 可由重排救回（→ 5C）

node_rrf 的 recall@k 掃描：

| k | recall@k | MRR |
|---|---|---|
| 10 | 0.795 | 0.484 |
| 20 | **0.936** | 0.484 |
| 30 | 0.949 | 0.469 |
| 50 | 0.949 | 0.467 |

recall@20 較 recall@10 暴增（0.795→0.936），代表 **~14% 目標其實被檢索進候選池、只是 RRF 排在第 11–20 名**。`search_memory_nodes` 的候選池已放大到 30（`_candidate_pool_limit`），這些目標已在池中，但只做 access_count 微調、未依 query 相關性重排。**加一個 cross-encoder 重排步驟可把它們拉進 top-10，同時提升 recall 與 MRR**（階段 5C）。recall@50 於 0.949 封頂，剩 ~5% 屬檢索層極限（重排救不了）。

### 4. 弱點 group（node_rrf recall<0.8）

`cix3752iWeb`（最大 group，0.667）、`SeleniumPelican`（0.333）、`web`（0.500）、`Valxe`（0.700）、`SheetAutomation`（0.667）、`LohasOwner-decisions`/`OnlinePixelAgents`/`cix3752iForwarderPlatform`（0.750）。這些多為程式碼/技術類英文短摘要，向量區辨度較低，是 5C 重排與後續調參的重點對象。

## 對後續階段的指引

- **階段 5C**：對 node 候選池加 cross-encoder 重排，目標把 node recall@10 從 0.795 拉向 ~0.93、MRR 由 0.484 提升。以 `data/eval_baseline_full.json` 為回歸基準（`--compare-baseline`）。
- edge 搜尋已達上限，5C 重排對 edge 預期增益有限，應以 node 為主。
