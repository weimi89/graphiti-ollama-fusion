# Graphiti MCP Server

Сервис памяти на основе графа знаний — MCP-сервер, объединяющий несколько провайдеров LLM (Ollama / GLM / GROQ / OpenRouter / DeepSeek) с графовой базой данных Neo4j.

Разработан на основе [getzep/graphiti](https://github.com/getzep/graphiti) с расширениями, поддерживает гибкое переключение между локальным Ollama и облачными LLM, а также позволяет независимо указывать провайдера Embedding (отделённого от LLM).

## Ключевые возможности

- **Интеллектуальное управление памятью** — использование графа знаний для хранения и извлечения сложных связей памяти
- **Семантический поиск** — гибридный поиск на основе векторных эмбеддингов (вектор + ключевые слова + обход графа)
- **16 стратегий поиска** — расширенный поиск поддерживает RRF, MMR, Cross-Encoder и другие способы переранжирования
- **Несколько провайдеров LLM** — поддержка Ollama (локально), GLM (智谱 AI, бесплатно), GROQ (высокоскоростной инференс), OpenRouter (агрегация моделей разных производителей), DeepSeek (深度求索), переключение одним ключом через переменную окружения
- **Отделение Embedding от LLM** — можно независимо указать эмбеддер через `EMBEDDING_PROVIDER`, облачные LLM автоматически откатываются на локальный `bge-m3`
- **Распределение по двум моделям** — в режиме Ollama сложные задачи используют основную модель, простые задачи автоматически переключаются на малую модель для повышения производительности
- **Интеллектуальное разбиение контента** — длинные тексты автоматически разбиваются на сегменты, снижая нагрузку на LLM (порог настраивается)
- **Фоновая обработка памяти** — добавление памяти может выполняться в фоне, вызов MCP возвращается немедленно
- **Дедупликация памяти** — автоматическое обнаружение высокосхожих существующих записей памяти во избежание дублирования
- **Обнаружение конфликтов** — обнаружение противоречивых фактов между двумя сущностями, выявление устаревшей и актуальной информации
- **Обнаружение сообществ** — автоматическая кластеризация связанных сущностей на основе алгоритма Label Propagation
- **Отслеживание важности** — автоматическая запись частоты доступа к сущностям, результаты поиска сортируются по важности
- **Интеллектуальное забывание** — выявление и очистка устаревших, редко используемых записей памяти для поддержания компактности графа
- **Массовый импорт** — единовременная отправка нескольких записей памяти, подходит для миграции больших объёмов данных
- **Структурированные триплеты** — прямое добавление «субъект-отношение-объект» с пропуском извлечения LLM, выполняется за секунды
- **Веб-интерфейс управления** — встроенная панель мониторинга, просмотр, поиск, визуализация графа знаний, AI-вопросы и ответы, просмотр сообществ
- **Многоязычность (i18n)** — сообщения ответов поддерживают 30+ локалей (включая zh-TW / en / zh-CN / ja / pt-BR / ko / es / de / fr и др.); инструменты MCP используют `SERVER_LANG`, REST API автоматически согласует язык по HTTP `Accept-Language`
- **Тёмная/светлая тема** — веб-интерфейс поддерживает переключение тем
- **Безопасный режим** — опциональное быстрое добавление памяти с пропуском извлечения сущностей
- **Поддержка Docker** — встроенный Dockerfile, поддержка контейнеризованного развёртывания
- **Безопасность при конкурентности** — asyncio.Lock защищает инициализацию, предотвращая состояния гонки
- **Многоуровневая проверка работоспособности** — `/health` (liveness) + `/health/ready` (readiness)

## Системные требования

| Пункт | Требование |
|------|------|
| Python | 3.10+ (рекомендуется 3.11+) |
| Neo4j | 4.0+ (`bolt://localhost:7687`) |
| Провайдер LLM | Ollama / GLM / GROQ / OpenRouter / DeepSeek (один из пяти) |
| Node.js | 18+ (только для фонового запуска через PM2, опционально) |
| Дисковое пространство | ~3GB (модели Ollama + данные Neo4j) |

### Выбор провайдера LLM

Переключение через переменную окружения `LLM_PROVIDER` (`ollama` / `glm` / `groq` / `openrouter` / `deepseek`):

| Провайдер | Особенности | Модель LLM | Embedding | Подходящий сценарий |
|--------|------|----------|-----------|----------|
| **Ollama** (по умолчанию) | Полностью локально, данные не покидают машину | `qwen2.5:3b` | `bge-m3` (отличное качество для китайского + RAG) | Есть GPU, важна приватность |
| **GLM** | Бесплатное облако, стабильно, без ограничений | `glm-4-flash` (бесплатно) | `embedding-3` | Нет GPU, сценарии с интенсивным поиском |
| **GROQ** | Сверхвысокая скорость инференса | `llama-3.3-70b-versatile` | Откат на Ollama `bge-m3` | Редкая запись, стремление к качеству |
| **OpenRouter** | Агрегация моделей разных производителей, включая бесплатные квоты | `stepfun/step-3.5-flash:free` и др. | Откат на Ollama `bge-m3` | Желание использовать конкретную облачную модель |
| **DeepSeek** | Облако 深度求索, высокая рентабельность | `deepseek-v4-flash` / `deepseek-v4-pro` | Откат на Ollama `bge-m3` | Понимание китайского, недорогое облако |

> **Отделение Embedding от LLM**: эмбеддер указывается независимо через `EMBEDDING_PROVIDER` (`ollama` / `glm`), при отсутствии настройки следует за `LLM_PROVIDER`. Фактически только `glm` использует GLM `embedding-3`, остальные (включая GROQ / OpenRouter / DeepSeek и другие облачные LLM, не предоставляющие Embedding) всегда автоматически используют Ollama `bge-m3`. **Поэтому при использовании любого облачного LLM по-прежнему требуется локальный Ollama для предоставления сервиса эмбеддинга (если embedding также не установлен в glm).**

#### Режим Ollama (локально)

```bash
# Основная модель LLM (рекомендуется qwen2.5:3b, лучший баланс скорости и стабильности)
ollama pull qwen2.5:3b

# Модель эмбеддинга (обязательно, для векторного поиска)
ollama pull bge-m3
```

> **Замечания по выбору модели**:
> - `qwen2.5:3b` — рекомендуется, ~2s/вызов, ~100 t/s, 100% стабильность структурированного вывода graphiti-core
> - `qwen2.5:7b` — лучшее качество, но медленнее в 5-10 раз, подходит для сценариев со стремлением к качеству
> - `qwen2.5:1.5b` — самая высокая скорость, но **нестабильна** (успешность структурированного JSON всего 33%), не рекомендуется к использованию

#### Режим GLM (облако 智谱 AI)

```bash
# Настройки .env
LLM_PROVIDER=glm
GLM_API_KEY=your_api_key          # получить с https://open.bigmodel.cn
GLM_MODEL=glm-4-flash             # бесплатная модель
GLM_EMBEDDING_MODEL=embedding-3
GLM_EMBEDDING_DIMENSIONS=768      # должно совпадать с размерностью векторного индекса Neo4j
```

> **Справка по производительности GLM**: запись ~22s (короткий текст), поиск ~0.34s, ноль ошибок Rate Limit, в 2-5 раз медленнее локального Ollama, но полностью бесплатно.

#### Режим GROQ (высокоскоростной инференс)

```bash
# Настройки .env
LLM_PROVIDER=groq
GROQ_API_KEY=your_api_key         # получить с https://console.groq.com
GROQ_MODEL=llama-3.3-70b-versatile
```

> **Примечание**: GROQ не предоставляет сервис Embedding, требуется использовать эмбеддер Ollama (автоматический откат) или установить `EMBEDDING_PROVIDER` в glm. У GROQ строгий Rate Limit, высокочастотное использование вызовет множество повторных попыток.

#### Режим OpenRouter (агрегация моделей разных производителей)

```bash
# Настройки .env
LLM_PROVIDER=openrouter
OPENROUTER_API_KEY=your_api_key       # получить с https://openrouter.ai/keys
OPENROUTER_MODEL=stepfun/step-3.5-flash:free   # можно заменить на любую модель OpenRouter
```

> **Примечание**: OpenRouter не предоставляет Embedding, автоматический откат на Ollama `bge-m3`. Список моделей см. на https://openrouter.ai/models (включает несколько бесплатных моделей `:free`).

#### Режим DeepSeek (深度求索)

```bash
# Настройки .env
LLM_PROVIDER=deepseek
DEEPSEEK_API_KEY=your_api_key         # получить с https://platform.deepseek.com
DEEPSEEK_MODEL=deepseek-v4-flash      # рекомендуется; или deepseek-v4-pro (лучшее качество)
```

> **Примечание**: DeepSeek не предоставляет Embedding, автоматический откат на Ollama `bge-m3`. `deepseek-chat` / `deepseek-reasoner` будут выведены из эксплуатации 2026-07-24, рекомендуется перейти на `deepseek-v4-flash` / `deepseek-v4-pro`. DeepSeek строго требует, чтобы prompt в режиме `json_object` содержал строку "json", в клиенте уже встроена резервная защита, дополнительных настроек не требуется.

## Быстрый запуск

### 1. Предварительная подготовка

Убедитесь, что Neo4j уже запущен на локальной машине, и подготовьте соответствующие сервисы в зависимости от выбранного провайдера LLM:

```bash
# Убедитесь, что Neo4j запущен (обязательно)
neo4j status
# Или используйте Docker: docker run -d -p 7687:7687 -p 7474:7474 -e NEO4J_AUTH=neo4j/your_password neo4j:latest

# Режим Ollama: убедитесь, что Ollama запущен
ollama list
# Если не запущен: ollama serve

# Режим GLM / GROQ: требуется только действительный API Key, локальные сервисы не нужны
```

### 2. Установка зависимостей

```bash
git clone <repo-url>
cd graphiti
uv sync
```

> **Примечание**: этот проект использует [uv](https://github.com/astral-sh/uv) для управления зависимостями. Если не установлен: `curl -LsSf https://astral.sh/uv/install.sh | sh`

### 3. Настройка окружения

```bash
cp .env.example .env
```

Отредактируйте `.env`, **как минимум** необходимо изменить следующие пункты:

```bash
NEO4J_PASSWORD=your_actual_password  # обязательно: пароль Neo4j
LLM_PROVIDER=ollama                  # ollama / glm / groq / openrouter / deepseek
OLLAMA_MODEL=qwen2.5:3b              # режим Ollama: локальная модель LLM
# GLM_API_KEY=your_key               # режим GLM: API Key 智谱 AI
# GROQ_API_KEY=your_key              # режим GROQ: GROQ API Key
# OPENROUTER_API_KEY=your_key        # режим OpenRouter: API Key
# DEEPSEEK_API_KEY=your_key          # режим DeepSeek: API Key
```

### 4. Запуск сервиса

```bash
# Режим HTTP (рекомендуется, включает веб-интерфейс управления)
uv run python graphiti_mcp_server.py --transport http --port 8000

# Или используйте фоновый запуск через PM2 (рекомендуется для длительной работы)
pm2 start ecosystem.config.cjs
```

### 5. Проверка сервиса

После запуска можно обращаться к следующим конечным точкам:

| Конечная точка | Описание |
|------|------|
| http://localhost:8000/ | Веб-интерфейс управления |
| http://localhost:8000/mcp | Конечная точка MCP (для подключения клиентов MCP) |
| http://localhost:8000/health | Проверка работоспособности (liveness) |
| http://localhost:8000/health/ready | Глубокая проверка (включая подключение к Neo4j) |
| http://localhost:8000/api/stats | Статистика REST API |

## Настройка клиента MCP

### Режим HTTP (рекомендуется)

Подходит для клиентов MCP с поддержкой HTTP, таких как Claude Code, Cline:

```json
{
  "mcpServers": {
    "graphiti-memory": {
      "type": "http",
      "url": "http://localhost:8000/mcp"
    }
  }
}
```

### Режим STDIO

Подходит для клиентов, требующих прямого запуска процесса, таких как Claude Desktop:

**Расположение файла конфигурации:**
- macOS: `~/Library/Application Support/Claude/claude_desktop_config.json`
- Windows: `%APPDATA%/Claude/claude_desktop_config.json`

```json
{
  "mcpServers": {
    "graphiti-memory": {
      "command": "uv",
      "args": [
        "run", "--directory", "/path/to/graphiti",
        "python", "graphiti_mcp_server.py", "--transport", "stdio"
      ],
      "env": {
        "NEO4J_URI": "bolt://localhost:7687",
        "NEO4J_USER": "neo4j",
        "NEO4J_PASSWORD": "your_password"
      }
    }
  }
}
```

> **Примечание**: режим SSE (`--transport sse`) больше не рекомендуется. В MCP 1.x есть проблемы совместимости инициализации сессии, используйте режим HTTP.

## Инструменты MCP (19 инструментов)

### Управление памятью (7 инструментов)

| Инструмент | Описание |
|------|------|
| `add_memory_simple` | Добавление памяти в граф знаний (поддержка фоновой обработки, интеллектуального разбиения, проверки дедупликации) |
| `add_episode_bulk` | Массовое добавление нескольких записей памяти (по умолчанию фоновая обработка) |
| `add_triplet` | Добавление структурированного триплета (пропуск LLM, выполняется за секунды) |
| `search_memory_nodes` | Поиск узлов памяти (поддержка 16 стратегий поиска, фильтрации по времени) |
| `search_memory_facts` | Поиск фактов памяти (поддержка фильтрации по типу отношений, временному диапазону, валидности) |
| `advanced_search` | Расширенный поиск (16 стратегий, возвращает узлы+рёбра+сообщества+фрагменты) |
| `get_episodes` | Получение последних фрагментов памяти |

### Анализ знаний (3 инструмента)

| Инструмент | Описание |
|------|------|
| `check_conflicts` | Обнаружение конфликтов фактов между двумя сущностями (актуальные vs устаревшие) |
| `get_node_edges` | Исследование входящих и исходящих рёбер узла |
| `build_communities` | Запуск обнаружения и кластеризации сообществ (по умолчанию фоновая обработка) |

### Обслуживание памяти (2 инструмента)

| Инструмент | Описание |
|------|------|
| `get_stale_memories` | Запрос устаревших, редко используемых записей памяти |
| `cleanup_stale_memories` | Очистка устаревшей памяти (по умолчанию режим предпросмотра dry_run) |

### Управление задачами

| Инструмент | Описание |
|------|------|
| `get_memory_task_status` | Запрос прогресса и результатов фоновой задачи обработки памяти |

### Удаление и запрос

| Инструмент | Описание |
|------|------|
| `delete_episode` | Удаление фрагмента памяти |
| `delete_entity_edge` | Удаление ребра сущности (отношения) |
| `get_entity_edge` | Получение подробной информации о ребре сущности |

### Системное управление

| Инструмент | Описание |
|------|------|
| `get_status` | Получение состояния сервиса (Neo4j, LLM, эмбеддер) |
| `test_connection` | Тестирование подключения Neo4j / LLM / эмбеддера |
| `clear_graph` | Очистка графовой базы данных (поддержка очистки по group_id) |

## Параметры инструментов

### add_memory_simple

| Параметр | Тип | Обязательный | Значение по умолчанию | Описание |
|------|------|------|--------|------|
| `name` | string | Y | | Имя записи памяти |
| `episode_body` | string | Y | | Содержимое памяти (свыше 800 символов автоматически разбивается) |

| `use_safe_mode` | bool | | `false` | Безопасный режим (пропуск извлечения сущностей, быстро, но память недоступна для поиска) |

> **Подсказки по производительности**:
> - Короткий текст (<800 символов): прямая обработка, обычно завершается за 30-40 секунд
> - Длинный текст (>800 символов): автоматическое разбиение на сегменты, параллельная обработка через `add_episode_bulk` (на ~33% быстрее последовательной)
> - Использование `background=true` позволяет избежать блокировки вызова MCP, отслеживайте прогресс через `get_memory_task_status`
> - `use_safe_mode=true` завершается за секунды, но память не может быть найдена инструментами search
> - При включённой дедупликации высокосхожие записи памяти получат предупреждение (`force=true` для пропуска)

## Конфигурация

### Переменные окружения (.env)

Конфигурация использует механизм наложения: файл конфигурации JSON в качестве основы, переменные окружения переопределяют отдельные значения.

```bash
# === Обязательно ===
NEO4J_URI=bolt://localhost:7687
NEO4J_USER=neo4j
NEO4J_PASSWORD=your_password        # необходимо изменить

# === Выбор провайдера LLM ===
LLM_PROVIDER=ollama                 # ollama / glm / groq / openrouter / deepseek

# === Провайдер Embedding (опционально, по умолчанию следует за LLM_PROVIDER) ===
# Только glm использует GLM Embedding, остальные всегда используют Ollama bge-m3
# EMBEDDING_PROVIDER=ollama         # ollama / glm

# === Конфигурация Ollama (используется при LLM_PROVIDER=ollama) ===
OLLAMA_MODEL=qwen2.5:3b             # основная модель (рекомендуется qwen2.5:3b)
OLLAMA_SMALL_MODEL=qwen2.5:3b       # малая модель (для простых задач, можно выбрать другую модель)
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_TEMPERATURE=0.1

# === Конфигурация GLM (используется при LLM_PROVIDER=glm) ===
GLM_API_KEY=your_api_key            # получить с https://open.bigmodel.cn
GLM_MODEL=glm-4-flash               # бесплатная модель
GLM_EMBEDDING_MODEL=embedding-3
GLM_EMBEDDING_DIMENSIONS=768

# === Конфигурация GROQ (используется при LLM_PROVIDER=groq) ===
GROQ_API_KEY=your_api_key           # получить с https://console.groq.com
GROQ_MODEL=llama-3.3-70b-versatile

# === Конфигурация OpenRouter (используется при LLM_PROVIDER=openrouter) ===
OPENROUTER_API_KEY=your_api_key     # получить с https://openrouter.ai/keys
OPENROUTER_MODEL=stepfun/step-3.5-flash:free

# === Конфигурация DeepSeek (используется при LLM_PROVIDER=deepseek) ===
DEEPSEEK_API_KEY=your_api_key       # получить с https://platform.deepseek.com
DEEPSEEK_MODEL=deepseek-v4-flash    # или deepseek-v4-pro

# === Модель эмбеддинга Ollama (используется при любом не-glm эмбеддинге) ===
OLLAMA_EMBEDDING_MODEL=bge-m3
OLLAMA_EMBEDDING_DIMENSIONS=768

# === Отображение и язык (опционально) ===
GRAPHITI_DISPLAY_TIMEZONE=Asia/Taipei # часовой пояс отображения временных меток в ответах API (имя IANA; хранение остаётся в UTC)
SERVER_LANG=zh-TW                     # язык ответов инструментов MCP (полный список локалей см. в src/i18n.py); REST API использует Accept-Language

# === Производительность памяти (опционально) ===
GRAPHITI_CHUNK_THRESHOLD=800         # пороговое количество символов для запуска интеллектуального разбиения
GRAPHITI_MAX_CHUNK_SIZE=600          # максимальное количество символов в сегменте
GRAPHITI_MAX_COROUTINES=10            # максимальное количество параллельных корутин
GRAPHITI_DEFAULT_BACKGROUND=false    # включена ли фоновая обработка по умолчанию

# === Отслеживание важности и интеллектуальное забывание (опционально) ===
ENABLE_IMPORTANCE_TRACKING=true      # включить отслеживание доступа

STALE_DAYS_THRESHOLD=30              # порог устаревания в днях
STALE_MIN_ACCESS_COUNT=2             # минимальное количество доступов
```

## Устранение неполадок

### Сбой подключения к Neo4j

```bash
neo4j status                              # проверка состояния сервиса
cypher-shell -u neo4j -p your_password    # подтверждение правильности пароля
curl http://localhost:7474                 # проверка HTTP-порта
```

Распространённые причины:
- Neo4j не запущен
- Неверный пароль (`NEO4J_PASSWORD` в `.env`)
- Порт занят или заблокирован брандмауэром

### Сбой подключения к LLM

**Режим Ollama:**
```bash
ollama serve                # запуск сервиса Ollama
ollama list                 # проверка установленных моделей
ollama pull qwen2.5:3b      # установка отсутствующей модели
```

Распространённые причины: Ollama не запущен, модель не установлена, недостаточно памяти GPU

**Режим GLM:**
- Подтвердите правильность `GLM_API_KEY`
- Подтвердите `GLM_EMBEDDING_DIMENSIONS=768` (должно совпадать с векторным индексом Neo4j)
- Конечная точка GLM API: `https://open.bigmodel.cn/api/paas/v4/`

**Режим GROQ:**
- Подтвердите правильность `GROQ_API_KEY`
- При частом Rate Limit рассмотрите переключение на режим GLM
- GROQ не предоставляет Embedding, нужно убедиться в доступности эмбеддера Ollama

**Режим OpenRouter:**
- Подтвердите правильность `OPENROUTER_API_KEY`, `OPENROUTER_MODEL` является действительным ID модели (см. https://openrouter.ai/models)
- Не предоставляет Embedding, нужно убедиться в доступности эмбеддера Ollama

**Режим DeepSeek:**
- Подтвердите правильность `DEEPSEEK_API_KEY`
- Если появляется `Prompt must contain the word 'json'`: это жёсткое требование режима `json_object` DeepSeek, в клиенте уже встроена резервная защита; если по-прежнему появляется, убедитесь, что используется последняя версия `src/deepseek_client.py`, и перезапустите сервис
- Не предоставляет Embedding, нужно убедиться в доступности эмбеддера Ollama

### Ошибка подключения MCP

Если появляется `Invalid request parameters` или `Received request before initialization was complete`:

1. Убедитесь в использовании транспортного режима HTTP (**не используйте SSE**)
2. Убедитесь, что в настройках клиента указано `"type": "http"`, `"url": "http://localhost:8000/mcp"`
3. Перезапустите сервис: `pm2 restart graphiti-mcp-http --update-env`
4. Выполните `/mcp` в Claude Code для повторного подключения

### Медленная скорость добавления памяти

- **Ollama**: проверьте размер модели (`qwen2.5:3b` в 5-10 раз быстрее `7b`), убедитесь в использовании GPU (`ollama ps`)
- **GLM**: каждый add_episode требует 10-20+ сетевых обращений к LLM, ~22s для короткого текста — нормальное значение
- **GROQ**: Rate Limit приводит к множеству повторных попыток, при частом использовании рекомендуется переключиться на GLM или Ollama
- Используйте `background=true` для избежания блокировки
- Понизьте `GRAPHITI_CHUNK_THRESHOLD`, чтобы длинные тексты разбивались раньше

### Миграция модели Embedding

После смены модели embedding (например, `nomic-embed-text` → `bge-m3`) можно использовать инструмент миграции для повторной генерации всех существующих векторов, обеспечивая единообразие качества поиска:

```bash
# Предпросмотр количества записей для миграции
uv run python tools/migrate_embeddings.py --dry-run

# Полная миграция (поддержка возобновления с точки прерывания)
uv run python tools/migrate_embeddings.py

# Миграция только указанной группы
uv run python tools/migrate_embeddings.py --group-id myproject

# Продолжение с точки прерывания (повторный запуск после прерывания)
uv run python tools/migrate_embeddings.py --resume
```

> **Совместимость**: `bge-m3` нативно имеет 1024 измерения, система автоматически усекает до 768 измерений для совместимости с существующим векторным индексом Neo4j. Данные до и после миграции могут сосуществовать, но рекомендуется выполнить полную миграцию для получения наилучшего качества поиска.
